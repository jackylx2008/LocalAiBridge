`dist/LocalAiBridge.exe`。

重新生成图标：

```powershell
.\.venv\Scripts\python.exe icons\generate_local_ai_bridge_icon.py
```

## 启动错误摘要

GUI 过去只显示 `llama-server 已异常退出，退出码 1` 和 Python traceback，无法直接说明底层原因。
现在客户端会记录本次启动前的错误日志位置，仅分析当前子进程新增的 stderr，避免把历史日志误认为
本次错误。

当前可识别并给出处理建议的错误包括：

- HTTP 监听端口被其他进程占用。
- 内存或显存不足。
- GGUF 模型文件无法加载或不兼容。
- 其他未知错误：提取最后一条关键底层错误，并指向完整日志。

端口冲突的提示示例：

```text
llama-server 启动失败（退出码 1）。问题本质：端口 8080 已被其他程序占用，
无法启动第二个本地 AI 服务。请关闭占用该端口的服务，或为其中一个服务改用其他端口。
```

GUI 实时日志不再展开整段 traceback；完整异常和底层输出仍保存在磁盘日志中，便于开发排查：

```text
logs/LocalAiBridge.log
logs/llama_server.err.log
logs/llama_server.out.log
```

本次更新没有改变 `common.env`、`config.yaml`、OpenAI 兼容 API 或默认端口。已有本机配置可以继续

修改其中一个项目的端口配置。
