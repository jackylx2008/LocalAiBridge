# 2026-09-30 更新说明：GUI 上下文长度设置

## 改动

- `llama-server -c` 的新配置默认值从 `8192` 改为 `32768` token（32K）。
- GUI“配置概览”新增上下文长度输入框。输入正整数并点击“保存并重新加载”后，程序先更新本机 `common.env` 的 `LLAMACPP_CTX_SIZE`，再用新值重新启动模型。
- 输入框旁新增“一键设为 16K”按钮，点击后保存 `16384` token 并重新加载。
- 无效输入会被拒绝，当前模型不会因输入错误而停止。加载期间两个设置按钮不可用。

## 使用与配置优先级

配置优先级为：进程环境变量 `LLAMACPP_CTX_SIZE`、本机 `common.env` 中的同名值、`config.yaml` 中的 32K 默认值。旧 `common.env` 若仍写着 `8192`，且进程没有同名环境变量，窗口会先显示 8192；用户可以在 GUI 中改为 32768 或点击 16K 按钮。GUI 保存到 `common.env`，下次打开窗口时继续使用；若进程另外设置了同名环境变量，该环境变量仍会覆盖文件值。本机 `common.env` 包含私有配置，不提交到 Git。

输入值不要求是 2 的幂，例如 `24576`、`30000` 和 `40960` 都是合法的正整数。llama.cpp 可能按内部粒度对齐实际上下文大小；按 256 的倍数逐档尝试更方便比较。当前 GUI 不接受 `0`。

## 容量与验证

模型元数据显示训练上下文为 262144 token，但这不是当前显卡可用上下文的保证。上下文越大，KV 缓存通常越占显存；并发请求也会影响可用容量。建议确认 32K 能稳定启动和推理后，再按 `36864`（36K）、`40960`（40K）等档位测试。此前模型运行时约 3.0 GiB 的显存余量不足以保证 64K 可用。

已验证：15 项自动化测试通过；GUI 控件可创建，16K 按钮会设置 `16384` 并调用重载流程；当前配置生成的命令包含 `-c 32768`。本次没有运行实际的 32K 长上下文推理或测量显存上限。
